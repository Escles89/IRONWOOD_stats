# Recipe plans (#8)

`apps/recipe-plan/` joins Recipe Calc and Planned next action. One versioned record under the existing character/mode planned-action key contains either the original manual action (v1) or a recipe plan (v2). Existing calculator targets remain previews. Use as plan copies the target, recipe/source choices, conversion inputs and quantity choices; later calculator edits do not change the active record. Satisfied targets stay saved and recalculate when their items are spent.

The recipe catalog adds the six gathering skills' current native action memberships to the existing crafting catalog. The shopping graph accepts this catalog, so shared gathering supplies, recipes and conversion inputs use the existing combined-demand stock allocation and cycle detection. Sole sources are saved at activation, including intermediate recipes; missing saved sources require another choice. Combat drops, purchases and conversions remain manual. Charcoal still reserves recipe wood before considering spare wood; projected conversion output does not satisfy native readiness.

Steps are presented in dependency order. The first ready step is stable for unchanged observations; a selected ready alternative is preferred. The running action is excluded from starts, with pending loot shown separately from required acquisition. A following dependent action may be displayed as blocked. Partial observations remain unavailable, never zero. Observation changes recalculate without network reads. Explicit Refresh reads and validates the native user response without replaying action loops or daily work.

Native quantities describe Ironwood's primary-output limit, not attempts or guaranteed output. A supported single-unit primary drop provides a base or nominal suggestion. Unsupported output needs an explicit player quantity. For that start, known per-unit native costs and the native craft limit gate readiness, while total chain requirements remain unknown. Unique recipes require one native quantity. Start revalidates the displayed token, owner, active record, current work, supplies, native controls and fresh server evidence. Changed steps require another click. The existing guarded native start is reused; recipe starts require explicit idle and never authorize collection. Confirmed starts retain recipe plans and leave later work waiting.

Collection has its own explicit Stop & collect / Collect completed work control. It uses the mounted native page and an invocation-private guarded stop receiver. It checks the captured batch before stopping and again at the request, records the native collection receipt independently, and never calls Start. Collection errors or partial outcomes retain the plan. Requirements are recalculated from the native observed inventory after collection, without carrying a stale pre-collection material refusal forward.

The combined panel uses the Quick Skills modal over the current page. Its native preparation uses the already-mounted app with skipLocationChange and restores the previous internal route; no new app iframe is bootstrapped. The original skill list and resume controls retain their behavior. Legacy manual Status starts keep their completed-batch contract; the global Start next summary requires separate collection.

## Validation

Assembled workflow fixtures cover preview/activation separation, target subtraction and intermediate stock, source choices and invalidation, Seeds and Compost, shared supplies, cycles, ready alternatives, manual conversions, uncertain and unique quantities, gathering progress, explicit continuous and completed-finite collection, changed-click rejection, native request races, failures, reload/owner isolation, satisfied-then-spent targets and read-only refresh. The original shopping, manual-action and Quick Skills suites remain regression coverage.

Live read-only UI validation used Ironwood v1.6.5 and the local loader. The existing Elite Key 100 target of 70,000, with 26,900 owned, derived 43,100 keys and 30,390 Onyx Essence after existing intermediate stock. Activation survived reload. Start next stayed disabled during the user's ongoing Defense action. Keyboard Tab moved from Close planner to Refresh recipe. At a 390 × 844 viewport the panel client width and scroll width both measured 372 px. No live Start or collection was requested; native transition acceptance is fixture evidence, not a claim of live gameplay execution.
