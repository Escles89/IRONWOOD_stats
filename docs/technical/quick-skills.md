# Quick skill panel integration

Current behavior is described in the feature sections below; dated validation entries are a chronological implementation record and may describe earlier layouts or capabilities. Use the [player guide](../user/README.md) for current controls and placement.

`apps/quick-skills/page.js` mounts `/skills` as a virtual page beneath Status in the native sidebar. Both surfaces use `renderQuickSkillList`, the same owner-scoped state and delegated controls; quantity/planner dialogs remain overlays. Page replacement respects the shared interaction hold. Native route hiding excludes both portal pages, and native navigation restores the original display values. Startup restores `/skills` after Angular mounts. A guarded `navigateToSyncWithBrowser` wrapper skips only popstate visits to `/skills` and `/status`, because Angular queues its history handler before the userscript listener and otherwise replaces those URLs with its fallback. Other routes and initial navigation retain the native behavior. `skills-page.test.cjs` covers rendering, navigation, dialog cancellation and this narrowly scoped guard.

`apps/quick-skills/` owns history, configured quantities, the shared controls, quantity prompts and orchestration. The controls mount into a preserved slot in the Current Loot header, moving to the right end of the queue summary for compact crafting. Native skill pages show Quick Loot only when the route matches the running skill and action. Controls mount after Stop & Loot or the complete native start-control group, preserving the Amount/Craft hierarchy without moving native buttons. The controls match its height and background colour; other native pages use the sidebar activity area. The Skills modal shares the Guide’s centered overlay and panel styles. The regular visible-page scheduler observes native running actions on every route. Repeated observations do not rewrite storage.

History uses a versioned, validated localStorage record under `iw-status-quick-skills-v1:` plus the serialized `[displayName, isSolo]` owner. Amounts use `skillId:actionId` keys, independently of the current queue. Unknown or changing ownership prevents mutation and persistence. Only actual `state.user.action` values supply history; navigation does not.

Finite amounts require both a crafting skill and recipe materials. Material costs alone do not imply a finite queue: Farming consumes Seeds and Compost through an unbounded native Gather action. Loading saved history clears the old finite classification for gathering and ignores its obsolete amount preferences. Amount dialogs show the recipe/output image with the skill and action names, falling back to the skill icon when item artwork is unavailable.

The native adapter discovers the skill ID map, navigation order, action metadata and material-limit function from the existing Ironwood runtime. Discovery uses structural signatures and fails closed when required metadata cannot be read. Native navigation buttons provide the full skill-page route. A remembered target loads its exact route in a disposable native frame; its enabled native start or quantity-submit control performs the mutation. The adapter does not construct endpoint calls or change native resource preferences.

Start uses the native start flow's existing stop/collection step. Quick Loot explicitly stops first and submits the same action, using the remaining finite quantity derived from the native primary output count. Native quantity inputs receive input/change events, and the actual Craft submit control is clicked. The shared visible prompt makes the quantity decision before submission, checks whole positive quantities, and rechecks the native material limit before mutation.

Request observation wraps the existing observable without an extra subscription. Stop responses contain the user directly; confirmed native loot is captured before the action service clears its loot. Start responses contain action/challenge data. Confirmation requires both explicit skill/action IDs in the response and the matching native running state. Missing receipts and known empty rewards remain distinct. Reward notifications are deduplicated while native errors and level-up notifications remain available.

Every attempted mutation reconciles the main game, including stop-success/start-failure. A later synchronization failure remains separate from the known gameplay outcome. Frames are removed on all exits; observers are restored after settled requests. A timed-out frame retains a revoked start guard until disposal so a late stop completion cannot submit a new action. The main route is never used to execute the switch.

After reconciliation, a visible Status dashboard refreshes its underlying native skill page to the confirmed current action through the existing router with `skipLocationChange`. This updates the DOM source for live progress, loot and materials while preserving the Status URL and history. Synchronizing services alone leaves the previous selected page idle after a switch. Other visible pages stay in place, and navigation away during refresh is respected. A source refresh failure is reported separately from the confirmed gameplay result.

`tests/apps/quick-skills.test.cjs` drives rendered controls and delegated events through the assembled feature, stubbing native pages/runtime, storage and time. It covers compact crafting, native routes, history, ownership, finite quantities, shortage fallback, current and unavailable targets, collection/start failures, timeout, contention, and synchronization errors. `collection-recaps.test.cjs` covers receipt subscriptions and notification handling. Run `npm run build` followed by `npm run check`.

Browser acceptance must distinguish layout/source checks from an actual gameplay switch. A successful fixture or read-only inspection does not establish that a real character switched successfully.

The quantity chooser reads owned output from native inventory and uses the native skill component’s `calcCraftTime` calculation with the page’s Stardust mode. Craft All and Target resolve to an explicit quantity and pass through the same supply recheck and native submission as Craft. Editing uses Save amount and Use max without starting an action, and always persists the explicit edited choice even when the old amount exceeds supply. The shortage-only replacement checkbox is limited to start prompts. An Always use max preference persists as `{ max: true, reuse: true }` under the same recipe/owner key; fixed preferences retain `{ amount, reuse }`. Manual Start resolves max from the native limit afresh and rechecks after preparing controls, including a zero-supply stop before dispatch. Quick Loot retains the remaining queue and planned starts retain their explicit planned quantity. The max toggle disables fixed quantity/target inputs while preserving the typed quantity if toggled back.

Skill progress reads the character’s native skill XP and uses the exported native level/XP threshold functions. The existing SkillPage route component supplies its pure `calcEstimates` method for each remembered action; no navigation or action start is required. Missing metadata or non-positive rates leave the ETA unknown, and the current action’s rate is never applied to other skills. Progress and estimates refresh with the panel render.

Live acceptance passed, as confirmed by the player on 2026-09-26. The repository check at commit preparation passed all 287 tests.

Skill leaderboard ranks are owned by `apps/quick-skills/leaderboards.js`. The native `getLeaderboards(mode)` read returns every skill in one response (multiplayer `1`, solo `2`). Rank extraction mirrors the native leaderboard: explicit row rank when supplied, otherwise its one-based list position. Only this character’s ranks and observation time are persisted under `iw-status-skill-ranks-v1:` plus the Quick Skills owner. A one-hour TTL survives reload; refresh runs only while the Skills list is open, visible and shared work is idle. An unexpired native board can satisfy the read. Concurrent reads are deduplicated, late results after owner changes are discarded, failures retain stale ranks with five-minute backoff, and malformed or unavailable data remains unknown. The focused skill-ranks suite covers these boundaries.

The leaderboard badge occupies its own grid column at the upper-right row edge, with action controls below it. Shared portal action geometry uses a 26px minimum height, 12px font and 14px button glyphs across Status, Skills, planner, calculator and dialogs. Native controls and full-row navigation remain separate. Live inspection verified matching 26px controls on Skills, the planner, Status and Options, plus all 16 skill rows without rank/control overlap or horizontal overflow at 390px.

The shared Skills list places the active row and compact recipe summary in a shared two-column overview on both the standalone page and modal. Each column needs 360 px; narrower containers stack them, and an idle summary uses the full row. Stop & Loot uses the existing native stop control and collection receipt, verifies the current owner/action immediately before dispatch, refuses any native restart, reconciles after attempted collection, and preserves history and quantity preferences. It pauses an enabled recipe runner before stopping so the character remains idle. It does not require the automation toggle. The stop suite covers gathering, crafting, combat, contention, changed ownership/action, collection failure and post-collection synchronization failure.

The live Current Action card opens Skills from its header, action details and combat display, including its idle state. The focusable shortcut wraps only this top area; Materials and Consumables remain outside it. Delegation excludes nested native/ARIA controls, links, editable content, modified clicks and selected text. A dedicated shortcut marker excludes the Guide’s illustrations. Enter/Space on the focused shortcut uses the same click path; closing Skills restores focus to the retained shortcut. The quick-skills click suite covers this shortcut and preservation of nested consumable, mastery and planner controls.
